## 本期速览

本周的主线不是新模型数量，而是 Agent 基础设施进入切换窗口：MCP 无状态化正式版将在 7 月 28 日落地，移除会话与 `initialize` 握手，生产 MCP Server 应按 breaking change 对待。DeepSeek 旧模型名在今天退役，仍在使用 `deepseek-chat` 或 `deepseek-reasoner` 的调用必须完成迁移。开源侧，FastMCP 与 codebase-memory-mcp 的活跃度凸显出两条更具体的需求：标准化 MCP 服务工程化，以及长任务中的代码库记忆。AI Coding 的三大 CLI 仍由 Claude Code、Codex 和 Gemini CLI 领跑，但其分化已从“是否能写代码”转向许可、企业控制面与模型生态。

本期将 FastMCP 从 Assess 上调至 Trial；Superpowers 连续四期缺少有效代码提交，触发严重衰减预警，建议移出常规雷达。合规方面，EU AI Act 高风险系统义务距 8 月 2 日仅剩一周多，任何面向欧洲用户的高风险用例应立即做分类和证据链盘点。

## 重点信号详解

### MCP 7/28 无状态化正式版

**象限**：Frameworks & Infrastructure  
**环位**：Adopt  
**跨源热度分**：3.0

**是什么**：MCP 即将迎来无状态化的规范切换，协议不再以服务端会话和 `initialize` 握手作为基础。请求应可路由到任意可用实例，认证、上下文和持久化必须由应用架构显式承担。

**为什么重要**：这是一项兼容性与运维模型同时变化的协议升级。对现有 MCP Server 而言，隐式保存在进程内或 session 内的数据、反向依赖初始化状态的客户端，以及 OAuth 接入方式都可能成为迁移断点。

**当前状态**：正式版时间点为 7 月 28 日，距离当前仅 4 天。FastMCP 等主流工具保持活跃，但不应假设所有第三方 Server 与 Client 已自动兼容。

**建议下一步**：今天盘点所有生产与开发 MCP Server；将 session 依赖、身份传递、状态存储、重试与幂等性逐项列为迁移清单，并在 7/28 前完成灰度回归。

---

### DeepSeek V4 模型名迁移

**象限**：Models & Research  
**环位**：Trial  
**跨源热度分**：3.0

**是什么**：旧的 `deepseek-chat` 与 `deepseek-reasoner` 模型名在 7 月 24 日退役，现有调用需要迁移至新模型名与对应能力档位。

**为什么重要**：这不是一般性产品更新，而是会让未迁移请求失败的兼容性截止日。对网关、配置中心、模型路由规则、离线脚本和回归基准都应做一次全量搜索。

**当前状态**：公开报道将其定义为今天的迁移期限；本报告不对未能通过官方文档复核的具体模型规格做扩展断言。

**建议下一步**：在 API 配置仓库和运行时参数中搜索旧模型名；替换后按关键业务场景执行回归，重点核验函数调用、流式输出、上下文长度和计费归因。

---

### FastMCP 与代码库记忆 MCP

**象限**：Frameworks & Infrastructure  
**环位**：Trial  
**跨源热度分**：2.8

**是什么**：FastMCP 代表 MCP Server 工程化框架，codebase-memory-mcp 则把代码库记忆封装成 MCP 能力。二者共同指向“让 Agent 可稳定访问工具与长时上下文”的基础层建设。

**为什么重要**：对业务研发而言，Agent 的瓶颈往往不在单次模型回答，而在工具协议一致性、数据访问授权、索引新鲜度和任务跨会话恢复。这两个方向比泛化 Agent 套壳更接近生产落地问题。

**当前状态**：两项目均有清晰开源许可和高频更新；不过 Star 不应替代安全评估，特别是记忆 MCP 需验证数据驻留、租户隔离、敏感代码脱敏与删除机制。

**建议下一步**：选择一个无敏感数据的内部服务，以 FastMCP 完成无状态 MCP 服务 PoC；为 codebase-memory-mcp 单独建立威胁建模和数据生命周期验收项，再决定是否接入真实代码库。
